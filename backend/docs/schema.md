# Database schema (milestones 2–6A)

`users`: application-generated UUID primary key and non-null `created_at`
(`timestamptz`, database `now()` default). There are no identity or auth fields.

`projects`: application-generated UUID primary key, indexed non-null `owner_id`,
non-null `name` (`varchar(100)`), and non-null `created_at` / `updated_at`
(`timestamptz`). `created_at` has a database `now()` default.

`fk_projects_owner_id_users` requires an existing owner and uses `ON DELETE
RESTRICT`. Deleting an owner with projects fails; no ORM cascade or database
cascade is configured. Duplicate names are allowed, including for the same owner.
`ck_projects_name_nonblank` requires a character outside PostgreSQL's POSIX
whitespace class, rejecting empty strings, spaces, tabs, and newlines.
Primary keys use `pk_<table>` and the owner index is `ix_projects_owner_id`.

UUIDs are generated by SQLAlchemy's `uuid4` insert default, not by PostgreSQL.
The supported timestamp write path is SQLAlchemy ORM inserts/updates or SQLAlchemy
Core statements built from the mapped table. `updated_at` uses an aware UTC Python
callable for insert and `onupdate`; it changes when an UPDATE is emitted and no
explicit updated_at value is supplied. A no-op ORM commit leaves it unchanged.
Explicit values override the default. Raw SQL and external writers must supply
and maintain updated_at themselves; no database trigger is installed.
PostgreSQL stores timestamptz instants in UTC. Use UTC database sessions for reads
and aware UTC application values; migration/test sessions explicitly select UTC.

Migrations are explicit. Neither API startup nor health endpoints create tables
or run migrations. The initial migration creates users, projects, and the owner
index; its downgrade removes those application tables. Downgrade is destructive
and is exercised only in a new disposable test database.

## API tokens (milestone 3)

`api_tokens`: application-generated UUID `id`, non-null indexed UUID `user_id`,
non-null `digest` (`varchar(64)`), non-null timezone-aware `created_at` with database
`now()` default, and nullable timezone-aware `revoked_at`. There is no raw-token
column. `uq_api_tokens_digest` creates a unique PostgreSQL index on the SHA-256
hex digest. `fk_api_tokens_user_id_users` uses `ON DELETE RESTRICT`, including
for revoked tokens. UUID and timestamp conventions match the existing models.

Management issuance generates 32 random bytes using Python secrets, encodes them
as URL-safe text with an `lv_` prefix, and hashes the **full token**. It prints raw
token material only after commit. Authentication compares the digest via the
unique index and requires revoked_at IS NULL. Token IDs are management identifiers,
not credentials. Revocation sets revoked_at using the database UTC instant and
preserves the first revocation time on repeated calls. Tokens do not expire in
this initial policy. No default accounts/tokens, identity fields, or cascades exist.

Revision `0002_api_tokens` adds only api_tokens and its indexes. Its downgrade
removes only that table, preserving users/projects, and is tested only in the
fixture-created disposable databases. `0001_users_projects` is unchanged.

## Private artifacts (milestone 5)

`artifacts`: UUID id; non-null indexed UUID project_id referencing projects with
ON DELETE RESTRICT; unique private storage_key (varchar(64)); nonnegative bigint
size_bytes, file_count, declared_uncompressed_bytes; SHA-256 hex sha256
(varchar(64)); and timezone-aware created_at with database now() default.
Constraint names follow the existing pk/fk/uq/ix/ck convention. There are no file
cascades: projects with artifacts cannot be deleted, and metadata deletion is not
exposed. Storage keys are server-generated UUID filenames, never API fields.
Revision 0003_artifacts follows unchanged 0002_api_tokens. Downgrades are tested
only in disposable databases and do not delete files. No existing migration changed.

## Queued execution requests (milestone 6A)

`runs`: application-generated UUID id; non-null indexed project_id FK directly
to projects.id; non-null artifact_id; status varchar(16), default queued and
constrained to queued; runtime_template varchar(32), constrained to
python-fastapi-v1 with no implicit template default; created_at timestamptz with
database now() default. There is no user_id: ownership is derived through projects.

`fk_runs_artifact_project` maps (artifact_id, project_id) to
artifacts.(id, project_id), enforcing consistency even for direct database writes.
The new `uq_artifacts_id_project_id` is logically redundant with the global
artifact PK, but PostgreSQL requires an explicit matching unique target for that
composite FK. It is added only in new revision 0004_runs after 0003_artifacts.
Both the direct project FK and composite artifact FK use ON DELETE RESTRICT.
No metadata/files are cascade-deleted. The downgrade removes runs and the new
pair constraint, preserving artifacts/projects; only disposable tests run it.

All records stay queued; no lifecycle processing exists. The runtime template is
an explicit client selection, not source-compatibility validation. Repeated POSTs
produce independent records: no quotas or idempotency keys are implemented yet.
Future milestones must explicitly migrate the status constraint/schema before
adding lifecycle transitions; no speculative lifecycle columns are present here.
